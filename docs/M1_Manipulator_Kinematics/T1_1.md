# ROS 2 Jazzy — RViz2 and TF

In this lesson you will **visualize a robot model** and explore its **TF frames** (transforms) using **RViz2** and the `urdf_tutorial` example package.


## 5) RViz2 basics (quick navigation)

In RViz2:
- **Left mouse drag**: rotate view
- **Right mouse drag / scroll**: zoom
- **Middle mouse drag (scroll click)**: pan
- The yellow marker indicates the current rotation center (you can move it by panning)

Take a minute to get comfortable moving around the robot.

---

## 6) RobotModel: links (rigid parts)

In RViz2, on the left panel:
- Find **RobotModel**
- Expand **Links**

A **link** is a rigid part of the robot (a physical piece).

You can:
- Enable/disable individual links (hide/show parts)
- Adjust **Alpha** (transparency) to see inside the model

This helps you understand the robot’s structure before you look at TF.

---

## 7) TF: frames and transforms (how parts are placed)

Enable the **TF** display in RViz2 and expand:

- **TF → Frames**

Each frame is a coordinate system attached to a robot part (often one per link/joint region).

### Axis color convention in ROS

In most ROS robots, frames follow this convention:

- **X** axis: **red** (forward)
- **Y** axis: **green** (left)
- **Z** axis: **blue** (up)

So when you see a TF frame in RViz2:
- red arrow = x
- green arrow = y
- blue arrow = z

### Why TF matters

RobotModel shows shapes (boxes/cylinders/meshes), but TF is what tells ROS:

- where each part is relative to others
- how parts move relative to each other

In practice, **TF is one of the most important things to get right** in ROS-based robots.

## 8) Move joints and observe TF updating live

Use the **Joint State Publisher GUI** sliders.

Try moving:
- a wheel joint (rotation)
- a gripper extension (translation)
- a head joint (rotation)

As you move a joint:
- the robot model changes pose
- the TF frames associated with that joint/link update in real time

### What to watch for

- For a **rotation joint**:
  - one axis stays fixed (the axis of rotation)
  - the other axes rotate around it

- For a **translation joint**:
  - the frame shifts linearly along an axis

A useful mental model:
- links are like your **upper arm** and **forearm**
- the joint (elbow) defines:
  - where the forearm is relative to the upper arm
  - how it moves when you bend your arm

## 9) Quick verification (terminal)

While the demo is running, check nodes:

```bash
ros2 node list
```

You should see nodes typically like:
- `robot_state_publisher`
- `joint_state_publisher` or `joint_state_publisher_gui`
- `rviz2`

You can also inspect TF topics:

```bash
ros2 topic list | grep tf
```

You should see:
- `/tf`
- `/tf_static`

## Verification and risks

### Preconditions to check
- You installed the correct Jazzy package: `ros-jazzy-urdf-tutorial`
- You sourced Jazzy: `source /opt/ros/jazzy/setup.bash`

### Common issues and mitigations
- **Launch command fails (package not found)**
  - Reinstall and confirm distro name: `ros-jazzy-urdf-tutorial`
- **RViz2 opens but robot is not visible**
  - Ensure RobotModel display is enabled
  - Check the **Fixed Frame** (often `base_link` or similar)
- **TF axes cluttered**
  - In TF display, disable most frames and enable only a few (start with `base_link`)
- **Joint State Publisher GUI not showing**
  - The launch may start `joint_state_publisher` instead of GUI depending on environment; the robot should still appear in RViz2. Try installing GUI package if needed:
    - `sudo apt install ros-jazzy-joint-state-publisher-gui`
