# Mobile Robot Simulation with Gazebo and ros2\_control

### Simulation Lab — Applied Robotics (12224)

---

## Overview

In this lab you will build a differential drive robot from scratch in URDF, wire it into Gazebo Harmonic using `ros2_control`, and verify that the kinematic model from the theory session produces physically correct motion.

By the end of this lab you will have:

1. A complete URDF robot model that spawns and drives in Gazebo
2. A `diff_drive_controller` translating `/cmd_vel` commands into wheel motion
3. Two Python nodes that make the kinematic mathematics observable at runtime

!!! info "Connection to T0\_1 — Mobile Robot Kinematics"
    This lab implements **Model 1: Differential Drive** from the theory session.
    The `wheel_separation` and `wheel_radius` parameters you will configure are
    exactly the geometric quantities \(2L\) and \(r\) from the kinematic matrix:

    \[
    \begin{bmatrix} w_L \\ w_R \end{bmatrix} = \frac{1}{r}
    \begin{bmatrix} 1 & -L \\ 1 & L \end{bmatrix}
    \begin{bmatrix} v \\ \omega \end{bmatrix}
    \]

    If those values are wrong, the robot will not behave correctly in turns.

## Part 1 — URDF

Build your robot description from scratch in
`mobile_robot_desc/urdf/mobile_robot.urdf.xacro`.

### What your URDF must contain

**Links** (at minimum):

| Link | Type | Notes |
|---|---|---|
| `base_footprint` | empty | Virtual link at ground level |
| `base_link` | box | Main chassis with mass, inertia, visual, collision |
| `wheel_lb_Link` | cylinder | Rear-left driven wheel |
| `wheel_rb_Link` | cylinder | Rear-right driven wheel |
| `caster_Link` | sphere | Front passive support, zero friction |

You may add sensor links (`lidar_frame`, `depth_cam`, `imu_link`) if your physical
robot has them, connected with fixed joints.

**Joints:**

| Joint | Type | Parent → Child |
|---|---|---|
| `base_footprint_to_base_link` | fixed | `base_footprint` → `base_link` |
| `wheel_lb_Joint` | continuous | `base_link` → `wheel_lb_Link` |
| `wheel_rb_Joint` | continuous | `base_link` → `wheel_rb_Link` |
| `caster_Joint` | fixed | `base_link` → `caster_Link` |

Driven wheel joints must rotate around the **Y axis** (`<axis xyz="0 1 0"/>`).

### Three additions required for Gazebo

Beyond the standard URDF structure you already know from M1, three blocks must
be added for simulation.

**Addition 1 — Gazebo Harmonic plugin**

Connects your URDF to the `gz_ros2_control` system and tells it where to find
the controller configuration:

```xml
<gazebo>
  <plugin filename="libgz_ros2_control-system.so"
          name="gz_ros2_control::GazeboSimROS2ControlPlugin">
    <parameters>$(find mobile_robot_desc)/config/diff_drive_controller.yaml</parameters>
  </plugin>
</gazebo>
```

!!! info "Connection to M2 — Gazebo + ros2\_control"
    This is the same plugin block you used in M2 for the articulated arm
    (`libgz_ros2_control-system.so`). The only difference is the controller
    type inside the YAML — `DiffDriveController` instead of
    `JointTrajectoryController`.

**Addition 2 — `ros2_control` hardware interfaces**

Declares which joints are controlled and how. Only the two rear driven wheels
need command interfaces. The caster requires nothing — it is handled entirely
by the physics engine:

```xml
<ros2_control name="GazeboSimSystem" type="system">
  <hardware>
    <plugin>gz_ros2_control/GazeboSimSystem</plugin>
  </hardware>

  <joint name="wheel_lb_Joint">
    <command_interface name="velocity"/>
    <state_interface name="position"/>
    <state_interface name="velocity"/>
  </joint>

  <joint name="wheel_rb_Joint">
    <command_interface name="velocity"/>
    <state_interface name="position"/>
    <state_interface name="velocity"/>
  </joint>
</ros2_control>
```

**Addition 3 — Wheel friction**

Driven wheels need traction. The caster must slide freely in all directions
so the robot can turn without the front support resisting lateral motion:

```xml
<!-- Driven wheels — high traction -->
<gazebo reference="wheel_lb_Link">
  <mu1 value="0.8"/>
  <mu2 value="0.8"/>
</gazebo>

<gazebo reference="wheel_rb_Link">
  <mu1 value="0.8"/>
  <mu2 value="0.8"/>
</gazebo>

<!-- Caster — zero friction, slides freely -->
<gazebo reference="caster_Link">
  <mu1 value="0.0"/>
  <mu2 value="0.0"/>
</gazebo>
```

!!! warning "Caster collision geometry must be a sphere"
    A cylinder has a preferred rolling axis and will resist lateral sliding even
    with zero friction. Use `<sphere>` for the caster's `<collision>` block.
    The `<visual>` can be any shape you prefer.

## Part 2 — Controller YAML

Place the following file at
`mobile_robot_desc/config/diff_drive_controller.yaml`.

The structure and parameter names come directly from the official
[ros2\_controllers documentation](https://control.ros.org/jazzy/doc/ros2_controllers/diff_drive_controller/doc/userdoc.html).
The values (`wheel_separation`, `wheel_radius`, joint names) come from your URDF.

```yaml
controller_manager:
  ros__parameters:
    update_rate: 100
    use_sim_time: true

    joint_state_broadcaster:
      type: joint_state_broadcaster/JointStateBroadcaster

    diff_drive_base_controller:
      type: diff_drive_controller/DiffDriveController

diff_drive_base_controller:
  ros__parameters:
    # ── Joint names must match the URDF exactly ───────────────────────────
    left_wheel_names:  ["wheel_lb_Joint"]
    right_wheel_names: ["wheel_rb_Joint"]

    # ── Physical parameters — read these from your URDF ──────────────────
    # wheel_separation = 2L = distance between the two rear wheel centers
    # wheel_radius     = r  = radius of each driven wheel
    wheel_separation: 0.15182
    wheel_radius:     0.033

    wheel_separation_multiplier: 1.0
    left_wheel_radius_multiplier: 1.0
    right_wheel_radius_multiplier: 1.0

    # ── Odometry ──────────────────────────────────────────────────────────
    publish_rate:   50.0
    odom_frame_id:  odom
    base_frame_id:  base_link
    pose_covariance_diagonal:  [0.001, 0.001, 0.0, 0.0, 0.0, 0.01]
    twist_covariance_diagonal: [0.001, 0.0,   0.0, 0.0, 0.0, 0.01]

    open_loop:      false
    enable_odom_tf: true

    # ── Command input ─────────────────────────────────────────────────────
    cmd_vel_timeout:  0.5
    use_stamped_vel:  true   # Jazzy default — expects TwistStamped

    # ── Velocity and acceleration limits ──────────────────────────────────
    linear.x.has_velocity_limits:    true
    linear.x.has_acceleration_limits: true
    linear.x.has_jerk_limits:        false
    linear.x.max_velocity:           0.5
    linear.x.min_velocity:          -0.5
    linear.x.max_acceleration:       1.0

    angular.z.has_velocity_limits:    true
    angular.z.has_acceleration_limits: true
    angular.z.has_jerk_limits:        false
    angular.z.max_velocity:           1.0
    angular.z.min_velocity:          -1.0
    angular.z.max_acceleration:       2.0
    angular.z.min_acceleration:      -2.0
```

!!! warning "use\_stamped\_vel: true"
    In ROS 2 Jazzy the `diff_drive_controller` expects `TwistStamped` on
    `/cmd_vel` by default. When using `teleop_twist_keyboard` you must add
    `--ros-args -p stamped:=True`, otherwise the robot will not move.

## Part 3 — Launch File

Create `mobile_robot_bringup/launch/gazebo.launch.xml`.

Your launch file must start the following nodes in order:

1. **`robot_state_publisher`** — parse the xacro and publish `/robot_description` and TF. Pass `use_sim_time:=true`.
2. **Gazebo Harmonic** — include the `gz_sim.launch.py` from `ros_gz_sim` with an empty world (`empty.sdf -r`).
3. **`ros_gz_sim create`** — spawn the robot into Gazebo from the `/robot_description` topic.
4. **`parameter_bridge`** — bridge `/clock` from Gazebo to ROS 2 (`rosgraph_msgs/msg/Clock`).
5. **`spawner joint_state_broadcaster`** — activate the joint state broadcaster.
6. **`spawner diff_drive_base_controller`** — activate the diff drive controller.
7. **`relay`** (from `topic_tools`) — bridge `/cmd_vel` → `/diff_drive_base_controller/cmd_vel` so Nav2 works out of the box.
8. **`differential_drive_node`** — from `mobile_robot_kinematics`.
9. **`odometry_node`** — from `mobile_robot_kinematics`.

!!! info "Connection to M2 — Gazebo + ros2\_control"
    Nodes 1–6 follow exactly the same pattern as the arm launch file
    (`ros_gazebo.launch.xml`) from M2. The only new additions are the relay
    node (7) and the two kinematic nodes (8–9).

### `differential_drive_node.py`

Implements the forward kinematic matrix from T0\_1 explicitly in code.
Subscribes to `/cmd_vel` and publishes computed wheel speeds to `/wheel_speeds`.

```python
#!/usr/bin/env python3
"""
differential_drive_node.py
Makes the kinematic model from T0_1 visible as running code.

    [w_L]   1  [1  -L] [v    ]
    [w_R] = ─  [1   L] [omega]
               r

Subscribes to /cmd_vel (TwistStamped) and publishes [w_L, w_R] in rad/s
to /wheel_speeds. This node is pedagogical — the actual Gazebo motion is
driven by the diff_drive_controller which implements the same matrix internally.
"""

import rclpy
from rclpy.node import Node
from geometry_msgs.msg import TwistStamped
from std_msgs.msg import Float64MultiArray


class DifferentialDriveNode(Node):
    def __init__(self):
        super().__init__('differential_drive_node')

        # Physical parameters — must match the URDF and controller YAML
        self.declare_parameter('wheel_radius',    0.033)    # r  [m]
        self.declare_parameter('half_separation', 0.07591)  # L  [m]

        self.r = self.get_parameter('wheel_radius').value
        self.L = self.get_parameter('half_separation').value

        self.sub = self.create_subscription(
            TwistStamped, '/cmd_vel', self.cmd_vel_callback, 10)

        self.pub = self.create_publisher(
            Float64MultiArray, '/wheel_speeds', 10)

        self.get_logger().info(
            f'Differential drive node ready — r={self.r} m  L={self.L} m')

    def cmd_vel_callback(self, msg: TwistStamped):
        v     = msg.twist.linear.x     # forward speed      [m/s]
        omega = msg.twist.angular.z    # angular velocity   [rad/s]

        # ── Kinematic matrix: T0_1 Model 1 ──────────────────────────────
        #   w_L = (v - L·ω) / r
        #   w_R = (v + L·ω) / r
        w_left  = (v - self.L * omega) / self.r
        w_right = (v + self.L * omega) / self.r

        out = Float64MultiArray()
        out.data = [w_left, w_right]
        self.pub.publish(out)


def main(args=None):
    rclpy.init(args=args)
    rclpy.spin(DifferentialDriveNode())
    rclpy.shutdown()
```

### `odometry_node.py`

Implements the inverse kinematic model — recovers body velocities from encoder
speeds and integrates them into a pose estimate.

```python
#!/usr/bin/env python3
"""
odometry_node.py
Implements the differential drive inverse kinematics for odometry.

Given wheel speeds [w_L, w_R] from encoders:

    v     = (r/2)  · (w_R + w_L)      ← average speed
    omega = (r/2L) · (w_R - w_L)      ← speed difference / track width

Integrates pose using Euler method and publishes /odom and TF odom→base_link.
Subscribes to /encoder_speeds (Float64MultiArray: [w_left, w_right] in rad/s).
"""

import math
import rclpy
from rclpy.node import Node
from std_msgs.msg import Float64MultiArray
from nav_msgs.msg import Odometry
from geometry_msgs.msg import TransformStamped
from tf2_ros import TransformBroadcaster


class OdometryNode(Node):
    def __init__(self):
        super().__init__('odometry_node')

        self.declare_parameter('wheel_radius',    0.033)
        self.declare_parameter('half_separation', 0.07591)

        self.r = self.get_parameter('wheel_radius').value
        self.L = self.get_parameter('half_separation').value

        # Robot state in the world frame
        self.x     = 0.0
        self.y     = 0.0
        self.theta = 0.0
        self.last_time = self.get_clock().now()

        self.sub = self.create_subscription(
            Float64MultiArray, '/encoder_speeds',
            self.encoder_callback, 10)

        self.odom_pub       = self.create_publisher(Odometry, '/odom', 10)
        self.tf_broadcaster = TransformBroadcaster(self)

        self.get_logger().info(
            f'Odometry node ready — r={self.r} m  L={self.L} m')

    def encoder_callback(self, msg: Float64MultiArray):
        w_left  = msg.data[0]
        w_right = msg.data[1]

        now = self.get_clock().now()
        dt  = (now - self.last_time).nanoseconds * 1e-9
        self.last_time = now

        # ── Inverse kinematic model → body velocities ────────────────────
        #   v     = (r/2) · (w_R + w_L)
        #   omega = (r / 2L) · (w_R - w_L)
        v     = self.r / 2.0       * (w_right + w_left)
        omega = self.r / (2.0 * self.L) * (w_right - w_left)

        # ── Euler integration ────────────────────────────────────────────
        #   x(t+dt)     = x(t)     + v·cos(θ)·dt
        #   y(t+dt)     = y(t)     + v·sin(θ)·dt
        #   theta(t+dt) = theta(t) + omega·dt
        self.x     += v * math.cos(self.theta) * dt
        self.y     += v * math.sin(self.theta) * dt
        self.theta += omega * dt

        self._publish(now, v, omega)

    def _publish(self, stamp, v, omega):
        # TF: odom → base_link
        t = TransformStamped()
        t.header.stamp    = stamp.to_msg()
        t.header.frame_id = 'odom'
        t.child_frame_id  = 'base_link'
        t.transform.translation.x = self.x
        t.transform.translation.y = self.y
        t.transform.translation.z = 0.0
        t.transform.rotation.z    = math.sin(self.theta / 2.0)
        t.transform.rotation.w    = math.cos(self.theta / 2.0)
        self.tf_broadcaster.sendTransform(t)

        # Odometry message
        odom = Odometry()
        odom.header.stamp    = stamp.to_msg()
        odom.header.frame_id = 'odom'
        odom.child_frame_id  = 'base_link'
        odom.pose.pose.position.x    = self.x
        odom.pose.pose.position.y    = self.y
        odom.pose.pose.orientation.z = math.sin(self.theta / 2.0)
        odom.pose.pose.orientation.w = math.cos(self.theta / 2.0)
        odom.twist.twist.linear.x    = v
        odom.twist.twist.angular.z   = omega
        self.odom_pub.publish(odom)


def main(args=None):
    rclpy.init(args=args)
    rclpy.spin(OdometryNode())
    rclpy.shutdown()
```

Expected values at full forward speed:

|---|---|---|

| Backward (`,`) | -15.15 | -15.15 |

| Right turn (`l`) | +2.30 | -2.30 |

These numbers follow directly from the kinematic matrix with \(r = 0.033\) m
and \(L = 0.07591\) m.
