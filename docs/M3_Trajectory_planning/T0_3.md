## 0. Getting started — base code

Clone the base repository and build it before beginning this practical:

```bash
#Source ROS 2
source /opt/ros/jazzy/setup.bash

# Clone the base repository
git clone https://github.com/Gulden8ag/Base_Example_ROS2.git
cd Base_Example_ROS2

# Install dependencies
sudo apt install \
    ros-jazzy-gz-ros2-control \
    ros-jazzy-ros2-controllers \
    ros-jazzy-ros-gz-sim \
    ros-jazzy-ros-gz-bridge \
    ros-jazzy-robot-state-publisher \
    ros-jazzy-rviz2 \
    ros-jazzy-xacro
pip install numpy

# Build
colcon build
source install/setup.bash
```

Verify the base system works before continuing:

*Terminal 1 — launch Gazebo + RViz*
```bash
cd
source /opt/ros/jazzy/setup.bash
cd ~/Base_Example_ROS2
source install/setup.bash
ros2 launch my_robot_bringup ros_gazebo.launch.xml
```

*Terminal 2 — send a test pose*
```bash
cd
source /opt/ros/jazzy/setup.bash
cd ~/Base_Example_ROS2
source install/setup.bash
ros2 service call /ee_pose my_robot_interfaces/srv/EEpose "{x: 0.3, y: 0.2, z: 0.5}"
```

The robot should move to the requested position. If it does, the base system is working correctly.

### What the existing service does

`XYZServerGazbo.py` exposes `/ee_pose`. When called it:

1. Solves **inverse kinematics** using Levenberg-Marquardt numerical IK — see [T0_3 — Numerical IK from DH Parameters](https://gulden8ag.github.io/robotica_aplicada/M1_Manipulator_Kinematics/T0_3/) for the full derivation.
2. Creates **one** `JointTrajectoryPoint` with the solution angles.
3. Sends it to `/arm_controller/follow_joint_trajectory`.

The controller receives that single target and interpolates on its own — you have no control over speed, acceleration, or path shape. That is the limitation this practical solves.

## Part 1 — Visualization with PlotJuggler

### Installation

```bash
sudo apt install ros-jazzy-plotjuggler-ros
```

### Launch

Open a new terminal while the simulation is running:

```bash
ros2 run plotjuggler plotjuggler
```

### Connecting to the robot

1. Click **Streaming** → **ROS2 Topic Subscriber** → **Start**.
2. Find `/joint_states` in the topic list.
3. Expand it: `position[0]`…`[5]`, `velocity[0]`…`[5]`, `effort[0]`…`[5]`.
4. Drag signals to the plot area. Right-click a panel to split it.

### Suggested panel layout

| Top | Middle | Bottom |
|-----|--------|--------|
| `position[0]`…`[5]` | `velocity[0]`…`[5]` | `effort[0]`…`[5]` |

Toggle individual joints by clicking their legend entries. All panels share a time axis — use **Sync** to align them.

### Deriving acceleration

PlotJuggler computes acceleration from velocity with no code changes. Right-click any velocity signal → **Apply function** → **∂/∂t**. The result is the numerical time-derivative, equivalent to the finite-difference acceleration described in [T0_1 — Acceleration graph](https://gulden8ag.github.io/robotica_aplicada/M3_Trajectory_planning/T0_1/#23-acceleration-graph).


> **What effort means in Gazebo:** the position controller applies torque proportional to position error (gain = 0.1, visible in your launch log). Effort is zero when the robot holds still. During a trapezoidal trajectory it spikes during the ramp-up and ramp-down phases — a direct visual confirmation of the [T0_1 — Ramps use](https://gulden8ag.github.io/robotica_aplicada/M3_Trajectory_planning/T0_1/#4-ramps-use) theory.
