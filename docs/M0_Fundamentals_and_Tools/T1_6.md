# ROS 2 Jazzy — Parameters in Python Nodes

In this lesson you will add **parameters** to an existing Python node (the **number publisher**) so you can change behavior **at runtime** without modifying code or rebuilding.

We will convert two hard-coded values into parameters:

- `number` (integer): the value to publish  
- `timer_period` (float): how often to publish (seconds)

---

## Parameter Concept

We will use a publisher code to show the concepto we already know the structure:

- A publisher
- A timer
- Publish a number periodically

Before parameters, the node usually contains hard-coded values like:

- `number = 2`
- `timer period = 1.0 s`

Problem:

- If we wanted a different number or frequency, you must edit code (and often rebuild).

Solution:

- Use **parameters**.

---

## Parameters in Python are a 2-step process

For each parameter:

1) **Declare** it (name + default value)  
2) **Get** its current value (then use it in your code)

### Why declare first?
Declaring registers the parameter in the node so:

- it appears in `ros2 param list`
- it can be overridden from the terminal
- its type is established (based on the default value)

---

## Add parameters in the constructor

Add these lines near the top of your node `__init__()` (before publishers/timers):

```python
# 1) Declare parameters (name, default_value)
self.declare_parameter("number", 2)          # int (type inferred from default)
self.declare_parameter("timer_period", 1.0)  # float (type inferred from default)

# 2) Get parameter values (IMPORTANT: .value is a property, not a method)
self.number_ = self.get_parameter("number").value
self.timer_period_ = self.get_parameter("timer_period").value
```

---

## Use the parameters in your publisher/timer

Now replace hard-coded values:

- Publish `self.number_` instead of `2`
- Create timer using `self.timer_period_` instead of `1.0`

Example:

```python
self.timer_ = self.create_timer(self.timer_period_, self.timer_callback)
```

And inside the callback:

```python
msg.data = self.number_
self.publisher_.publish(msg)
```

---

## Full example node

This version publishes `std_msgs/msg/Int64` on topic `/number`.

```python
#!/usr/bin/env python3

import rclpy
from rclpy.node import Node
from std_msgs.msg import Int64


class NumberPublisher(Node):
    def __init__(self):
        super().__init__("number_publisher")

        # ---- Parameters (declare -> get) ----
        self.declare_parameter("number", 2)
        self.declare_parameter("timer_period", 1.0)

        self.number_ = self.get_parameter("number").value
        self.timer_period_ = self.get_parameter("timer_period").value

        # ---- Publisher + timer ----
        self.publisher_ = self.create_publisher(Int64, "number", 10)
        self.timer_ = self.create_timer(self.timer_period_, self.timer_callback)

        self.get_logger().info(
            f"Started number_publisher with number={self.number_}, timer_period={self.timer_period_}"
        )

    def timer_callback(self):
        msg = Int64()
        msg.data = int(self.number_)  # ensure int for Int64
        self.publisher_.publish(msg)


def main(args=None):
    rclpy.init(args=args)
    node = NumberPublisher()
    rclpy.spin(node)
    rclpy.shutdown()


if __name__ == "__main__":
    main()
```

## Build and run

Build your Python package:

```bash
cd ~/your_ws
colcon build --packages-select my_py_pkg
source install/setup.bash
```

Run normally:

```bash
ros2 run my_py_pkg number_publisher
```

Expected behavior:
- Publishes `2` every `1.0` seconds

---

## Inspect parameters from the terminal

While the node is running:

```bash
ros2 param list
```

You should see your node parameters, for example:

- `/number_publisher.number`
- `/number_publisher.timer_period`

---

## Override parameters at runtime

Stop the node and run again, but override values:

```bash
ros2 run my_py_pkg number_publisher --ros-args -p number:=3 -p timer_period:=0.5
```

Expected behavior:
- Publishes `3` every `0.5` seconds

Override only one parameter:

```bash
ros2 run my_py_pkg number_publisher --ros-args -p number:=3
```

Expected behavior:
- Publishes `3` every `1.0` seconds (timer_period default still used)

---

## Verify publishing

In another terminal:

```bash
ros2 topic echo /number
```

You should see the number changing based on parameters.

## YAML parameter files

We could create a **YAML File** and load the parameters at runtime.

Why this matters:
- A real node can have **dozens** of parameters.
- Passing many `-p name:=value` arguments in the terminal becomes slow and error-prone.
- YAML lets you save multiple configurations and reuse them easily.

> In the next section (launch files), you will typically **install** YAML files inside the workspace and load them from launch.  
> For now, you can place them anywhere (e.g., your home directory).

---

## Create a folder for YAML parameter files

Example (any location is fine for now):

```bash
mkdir -p ~/yaml_params
```

Create a file:

```bash
touch ~/yaml_params/number_params.yaml
```

---

## YAML structure (single node)

A ROS 2 params YAML file uses this structure:

- **Top level key** = node name
- Inside: `ros__parameters:`
- Inside: list of parameters as `name: value`

Example for a node named `/number_publisher`:

```yaml
number_publisher:
  ros__parameters:
    number: 5
    timer_period: 0.7
```

### Critical rules
- Node name must match **exactly**.
- Indentation matters (use spaces, commonly 2 spaces per level).
- Parameter values must match the **type** declared in code.

---

## Run the node using the YAML file

Instead of many `-p` flags, run:

```bash
ros2 run my_py_pkg number_publisher --ros-args --params-file ~/yaml_params/number_params.yaml
```

Verify:

```bash
ros2 topic echo /number
```

You should see `5` published, and the timing should reflect `timer_period: 0.7`.

If you want to check the publish rate:

```bash
ros2 topic hz /number
```

(If the period is `0.7`, the frequency is about `1 / 0.7 ≈ 1.4 Hz`.)

---

## YAML structure (multiple nodes in one file)

A single YAML file can contain parameter sets for **many nodes**.

Example:

```yaml
number_publisher_one:
  ros__parameters:
    number: 5
    timer_period: 0.7

number_publisher_two:
  ros__parameters:
    number: 3
    timer_period: 1.0
```

How it works:
- When a node starts with `--params-file ...`, it checks:
  - “Is there an entry in this YAML matching my node name?”
- If yes → it loads that parameter block.
- If no → it ignores the file (node uses default parameter values).

---

## Run two nodes with different configs (same YAML)

### Start Node 1 (rename to match YAML)

```bash
ros2 run my_py_pkg number_publisher   --ros-args -r __node:=number_publisher_one   --params-file ~/yaml_params/number_params.yaml
```

### Start Node 2 (rename to match YAML)

```bash
ros2 run my_py_pkg number_publisher   --ros-args -r __node:=number_publisher_two   --params-file ~/yaml_params/number_params.yaml
```

### Verify both are publishing

```bash
ros2 topic echo /number
```

You should see values from both nodes (e.g., `5` and `3`) arriving at different rates.
