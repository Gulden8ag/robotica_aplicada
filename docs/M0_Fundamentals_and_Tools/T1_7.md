# ROS 2 Jazzy — Launch Files (XML) + Parameters (Inline and YAML)

In this lesson you will create a **dedicated bringup package** to store:

- Launch files (`launch/`)
- Configuration files (`config/`) YAML parameter files

Then you will create an **XML launch file** that starts multiple nodes, and you will set parameters:

1) **Inline** in the launch file  
2) **From a YAML file** installed with the bringup package

---

## Create a dedicated bringup package

From your workspace `src/` folder:

```bash
cd ~/your_ws/src
ros2 pkg create my_robot_bringup
```

Why this package exists:

- You keep **launch files + configs** in one place
- Cleaner dependencies and project structure

### Clean up folders you do not need

```bash
cd my_robot_bringup
rm -rf include src
mkdir -p launch
mkdir -p config
```

Your bringup package should look like:

```text
my_robot_bringup/
  package.xml
  CMakeLists.txt
  launch/
  config/
```

---

## Install `launch/` and `config/` folders (CMake)

Open `my_robot_bringup/CMakeLists.txt` and keep it minimal.

Between `find_package(...)` and `ament_package()` add:

```cmake
install(DIRECTORY
  launch
  config
  DESTINATION share/${PROJECT_NAME}/
)
```

This installs both folders into:

```text
~/your_ws/install/my_robot_bringup/share/my_robot_bringup/
```

> You only do this once. After that, any file you put inside `launch/` or `config/` will be installed automatically after rebuilding.

---

## Create your first XML launch file

Create:

```bash
touch launch/number_app.launch.xml
```

Minimal structure:

```xml
<launch>
</launch>
```

Everything you add goes inside the `<launch> ... </launch>` tags.

---

## Start two nodes from the launch file

Example application:

- Start `number_publisher` 
- Start `number_counter` 

Edit `launch/number_app.launch.xml`:

```xml
<launch>

  <node pkg="my_py_pkg" exec="number_publisher" />

  <node pkg="my_cpp_pkg" exec="number_counter" />

</launch>
```

How to think about it:

- If you can run a node with:
  - `ros2 run <pkg> <exec>`
- Then the launch node line is basically the same:
  - `<node pkg="..." exec="..." />`

---

## Add runtime dependencies in `package.xml`

Because `my_robot_bringup` *launches* executables from other packages, add them as **execution dependencies**.

Open `my_robot_bringup/package.xml` and add:

```xml
<exec_depend>my_pkg</exec_depend>
```


In other words, each time you reference a new package in your launch file, add it as an `<exec_depend>`.

---

## Build and run the launch file

Build only the bringup package:

```bash
cd ~/your_ws
colcon build --packages-select my_robot_bringup
source install/setup.bash
```

Launch:

```bash
ros2 launch my_robot_bringup number_app.launch.xml
```

Verify:

```bash
ros2 node list
ros2 topic list
```

---

## Set parameters inside the launch file

If your `number_publisher` node declares parameters (example: `number`, `timer_period`), you can set them inside its `<node>` tag.

Update the `number_publisher` node tag:

```xml
<launch>

  <node pkg="my_py_pkg" exec="number_publisher">
    <param name="number" value="6" />
    <param name="timer_period" value="1.5" />
  </node>

  <node pkg="my_cpp_pkg" exec="number_counter" />

</launch>
```

Notes:

- Parameter names must match exactly what you declared in code (`declare_parameter(...)`).
- Values must match the parameter type.

Verify quickly:

```bash
ros2 param get /number_publisher number
ros2 param get /number_publisher timer_period
```

## Install and load parameters from a YAML file

For bigger nodes with many parameters, use YAML.

### Create a YAML file inside `config/`

Create inside `my_robot_bringup/config/`:

```bash
touch config/number_app.yaml
```

Example YAML:

```yaml
number_publisher:
  ros__parameters:
    number: 6
    timer_period: 1.5
```

### Load the YAML file from XML launch

Replace the inline params with:

```xml
<launch>

  <node pkg="<pkg_name>" exec="<exec_name>">
    <param from="$(find-pkg-share my_robot_bringup)/config/<filename>.yaml" />
  </node>

</launch>
```

Key idea:

- `$(find-pkg-share <launch_pkg>)` finds the installed path of your bringup package
- Then you append `/config/number_app.yaml`

### Build and run again

```bash
cd ~/your_ws
colcon build --packages-select my_robot_bringup
source install/setup.bash
ros2 launch my_robot_bringup number_app.launch.xml
```

You should get the same parameter values, but now they come from YAML.
