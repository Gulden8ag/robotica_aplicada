# ROS2 Jazzy — Custom Interface Message

In this lesson you will create your **first custom ROS 2 interface** by defining a **custom message** (`.msg`) and building it so it becomes available.

We will create:

- Package: `my_robot_interfaces`
- Message: `msg/HardwareStatus.msg`

This message will represent a simple “robot hardware status” payload (temperature, readiness flag, debug string).

---

## 1) Where should custom interfaces live?

Technically, you *can* place message/service definitions in many packages.

In practice, it is much cleaner to put **all custom interfaces** in **one dedicated package**, for example:

- `my_robot_interfaces`

Why this helps:

- Avoids dependency chaos later
- Other packages only need **one dependency**: the interface package
- Your app becomes easier to scale and maintain

> You only create the interface package **once**.  
> After that, adding a new interface is just: **create file → add it to CMake → build**.

---

## 2) Create an interface package

From your ROS 2 workspace `src/` folder:

```bash
cd ~/your_ws/src
ros2 pkg create my_robot_interfaces
```

Naming recommendation:

- Use your application/robot name + `_interfaces`
- Example: `ackerman_interfaces`, `ibero_robot_interfaces`, `abc_interfaces`

After creation you will see a typical CMake package structure:

```text
my_robot_interfaces/
  CMakeLists.txt
  package.xml
  include/        (not needed for interfaces)
  src/            (not needed for interfaces)
```

### Clean up the package (optional but recommended)

Remove folders you will not use:

```bash
cd my_robot_interfaces
rm -rf include src
```

Now the package is minimal:

```text
my_robot_interfaces/
  CMakeLists.txt
  package.xml
```

---

## 3) Configure `package.xml` (required lines)

Open `my_robot_interfaces/package.xml` and add **three lines** required for `rosidl` interface generation:

```xml
<buildtool_depend>rosidl_default_generators</buildtool_depend>
<exec_depend>rosidl_default_runtime</exec_depend>
<member_of_group>rosidl_interface_packages</member_of_group>
```

A typical placement is right after the existing `ament_cmake` dependency.

**Result (snippet example):**
```xml
<buildtool_depend>ament_cmake</buildtool_depend>

<buildtool_depend>rosidl_default_generators</buildtool_depend>
<exec_depend>rosidl_default_runtime</exec_depend>
<member_of_group>rosidl_interface_packages</member_of_group>
```

---

## 4) Configure `CMakeLists.txt`

Open `my_robot_interfaces/CMakeLists.txt`.

You need three key parts:

1) Find generators  
2) Generate interfaces  
3) Export runtime dependencies

Go from this (default):

```cmake
cmake_minimum_required(VERSION 3.8)
project(my_robot_interfaces)

if(CMAKE_COMPILER_IS_GNUCXX OR CMAKE_CXX_COMPILER_ID MATCHES "Clang")
  add_compile_options(-Wall -Wextra -Wpedantic)
endif()

# find dependencies
find_package(ament_cmake REQUIRED)
# uncomment the following section in order to fill in
# further dependencies manually.
# find_package(<dependency> REQUIRED)

if(BUILD_TESTING)
  find_package(ament_lint_auto REQUIRED)
  # the following line skips the linter which checks for copyrights
  # comment the line when a copyright and license is added to all source files
  set(ament_cmake_copyright_FOUND TRUE)
  # the following line skips cpplint (only works in a git repo)
  # comment the line when this package is in a git repo and when
  # a copyright and license is added to all source files
  set(ament_cmake_cpplint_FOUND TRUE)
  ament_lint_auto_find_test_dependencies()
endif()

ament_package()
```

to this, were we added a few dependencies and the interface generation block:

```cmake
cmake_minimum_required(VERSION 3.8)
project(my_robot_interfaces)

if(CMAKE_COMPILER_IS_GNUCXX OR CMAKE_CXX_COMPILER_ID MATCHES "Clang")
  add_compile_options(-Wall -Wextra -Wpedantic)
endif()

# find dependencies
find_package(ament_cmake REQUIRED)
find_package(rosidl_default_generators REQUIRED)

rosidl_generate_interfaces(${PROJECT_NAME}
  
)

ament_export_dependencies(rosidl_default_runtime)

ament_package()
```

### Notes
- Put **one interface per line** inside `rosidl_generate_interfaces(...)`
- No commas between lines
- Paths are relative to the package root (e.g., `msg/HardwareStatus.msg`)

---

## 5) Create your first message

Inside `my_robot_interfaces/`, create the message folder:

```bash
mkdir -p msg
```

Create the message file:

```bash
touch msg/HardwareStatus.msg
```

and add it to `CMakeLists.txt`:

```cmake
rosidl_generate_interfaces(${PROJECT_NAME}
  "msg/HardwareStatus.msg"
)
```

### Naming rules

For interface files:

- Use **UpperCamelCase** (start uppercase, each word starts uppercase)
- No underscores, no dashes in the filename
- Don’t include redundant words like “Message”


---

## 6) Define message fields

Edit `msg/HardwareStatus.msg`:

```text
float64 temperature
bool are_motors_ready
string debug_message
```

### Rules for fields
- One field per line
- Format: `<type> <name>`
- Use underscores for multiword field names (snake_case)
- No commas or punctuation

Primitive types used here:

- `float64`
- `bool`
- `string`

---

## 7) Build the interface package

Go to the workspace root (not inside `src/`):

```bash
cd ~/your_ws
colcon build --packages-select my_robot_interfaces
```

The first build that generates interfaces can take longer than usual.

Then source your workspace, as we created a new package with new interfaces:

```bash
source install/setup.bash
```

> If you open a new terminal later, you must source again. Unless you have added the source line to your `~/.bashrc` .

---

## 8) Verify the interface exists

Use `ros2 interface show` to confirm your message is discoverable:

```bash
ros2 interface show my_robot_interfaces/msg/HardwareStatus
```

Expected output:

```text
float64 temperature
bool are_motors_ready
string debug_message
```

## 9) Publish your custom message

Now we will modify our template node to publish messages of type:

- `my_robot_interfaces/msg/HardwareStatus`

---

### 1) Add the dependency to your Python package

Edit your Python package `package.xml` (example: `my_py_pkg/package.xml`) and add:

```xml
<depend>my_robot_interfaces</depend>
```

---

### 2) Modify the template node to publish `HardwareStatus`

Add the import:

```python
from my_robot_interfaces.msg import HardwareStatus
```

Create a publisher in `__init__()`:

```python
self.publisher_ = self.create_publisher(HardwareStatus, "hardware_status", 10)
```

Create a timer:

```python
self.timer_ = self.create_timer(0.5, self.publish_status)
```

Add the publish method:

```python
def publish_status(self):
    msg = HardwareStatus()
    msg.temperature = 36.5
    msg.are_motors_ready = True
    msg.debug_message = "OK"

    self.publisher_.publish(msg)
```

---

### 3) Full updated template node

```python
#!/usr/bin/env python3

import rclpy
from rclpy.node import Node

from my_robot_interfaces.msg import HardwareStatus


class MyNode(Node):
    def __init__(self):
        super().__init__("py_test")

        # Publisher using the custom message type
        self.publisher_ = self.create_publisher(HardwareStatus, "hardware_status", 10)

        # Publish at 2 Hz
        self.timer_ = self.create_timer(0.5, self.publish_status)

    def publish_status(self):
        msg = HardwareStatus()
        msg.temperature = 36.5
        msg.are_motors_ready = True
        msg.debug_message = "OK"

        self.publisher_.publish(msg)


def main(args=None):
    rclpy.init(args=args)
    my_node = MyNode()
    rclpy.spin(my_node)
    rclpy.shutdown()

if __name__ == "__main__":
    main()
```

---

### 4) Build and run

Before building dont forget to add the new dependency to add the entry point in `setup.py` 

Build your Python package (and source):

```bash
cd ~/your_ws
colcon build --packages-select my_py_pkg --symlink-install
source install/setup.bash
```

Run the node:

```bash
ros2 run my_py_pkg <your_executable_name>
```

---

### 5) Verify from terminal

Check the topic exists:

```bash
ros2 topic list
```

Inspect the topic type:

```bash
ros2 topic info /hardware_status
```

Echo messages:

```bash
ros2 topic echo /hardware_status
```

You should see:

- `temperature`
- `are_motors_ready`
- `debug_message`
