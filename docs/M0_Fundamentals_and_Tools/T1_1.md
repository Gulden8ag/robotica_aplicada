# First Program in ROS 2

We will start with our first program in ROS 2.

To implement programs, the normal workflow is:

1. Create the workspace directory
2. Create a package inside the `src` folder
3. Implement a node
    1. Create a node
    2. Create a publisher/client/etc
    3. add parameters if needed
4. Create a launch file 
5. Build the workspace
6. Source the workspace
7. Run the nodes
8. Verify


## Create a workspace and package

We will start by creating a ROS2 workspace. A workspace is a directory where we can build and store our ROS2 packages. The basic Layout is as follows:

```text
your_workspace_name/
 ├── src/
    ├── your_package_name/
```

A workspace can contain multiple packages, but for this example we will create a single package.

To create the workspace, open a terminal and go with the following steps.

1. Create the workspace directory and the `src` folder inside it:

    ```bash
    mkdir -p workspace_name/src
    ```
    - `mkdir` means make directory
    - `-p` means create parent directories if they do not exist.

2. Then, navigate to the workspace:

    ```bash
    cd workspace_name/src
    ```

3. create an empty package:

    ```bash
    ros2 pkg create <package_name> --build-type ament_python --dependencies rclpy
    ```

    This will create a package for python with the name `<package_name>` and with the dependency `rclpy`, which is the ROS 2 client library for Python.

4. Open VS Code from `src` folder:

    ```bash
    code .
    ```

5. Here we would modify and create the files for our package. We we will do this later.

6. We go back to our terminal and navigate to the workspace root

    ```bash
    cd ..
    ```

7. Build the workspace with colcon:

    ```bash
    colcon build
    ```
    optionally we can `--packages-select <package_name>` to build only a specific package, if not it will build all packages in the workspace.

    ??? Note
        If you have not sourced ROS 2 in your terminal, you will need to do it before building the workspace:

        ```bash
        source install/setup.bash
        ```

        also you can source colcon autocompletion if it's not working:

        ```bash
        /usr/share/colcon_argcomplete/hook/colcon-argcomplete.bash
        ```

        Finally there's an option to run colcon with `--symlink-install` which will create symlinks to the source files instead of copying them to the install folder. This is useful for development as you don't need to rebuild the package every time you make a change. Make sure that the python files are executable with `chmod +x <file_name>.py`.

## Create a Node

We have created and built our package, but we have not implemented any functionality yet.  Let's create a simple node template to work with.

We will open again VS Code in our source folder, an then create a new python file inside the package folder, remember that the structure is like this:
```text
src/
 ├── your_package_name/
        ├── your_package_name/
               ├── __init__.py
               ├── your_node.py  <--- create this file
```

### Minimal Node

1. We will add an interpreter line, this will say we are using python3 to run this script in case anything tries to run it directly.

    ```python
    #!/usr/bin/env python3
    ```
2. We will add the rclpy library and import the Node class from it.
    ```python
    import rclpy
    from rclpy.node import Node
    ```
3. Create a main function where we initialize and shutdown at minimum.
    ```python
    def main(args=None):
        rclpy.init(args=args) # Initialize rclpy

        rclpy.shutdown()      # Shutdown rclpy
    ```
4. Create the node, and add actions to it

    ```python
        node = Node("node_name")  # Create the node with the name "node_name"
        node.get_logger().info("Node has been started, hello Node")  # Log info message
    ```
5. Finally, we add the standard python main check to run the main function

    ```python
    if __name__ == "__main__":
        main()
    ```
Here's the complete code:
```python
#!/usr/bin/env python3

import rclpy
from rclpy.node import Node

def main(args=None):
    rclpy.init(args=args) # Initialize rclpy
    node = Node("node_name")  # Create the node with the name "node_name"
    node.get_logger().info("Node has been started, hello Node")  # Log info message
    rclpy.shutdown()      # Shutdown rclpy

if __name__ == "__main__":
    main()
```

make sure to save the file.

Let's go back to the terminal. Using the `cd` command navigate to the node file folder, where we can run the node, and make it executable.

```bash
cd ~/workspace_name/src/your_package_name/your_package_name
chmod +x your_node.py
```
you can check if it's executable with `ls` which will show the file executable in a different color. Which we will run next just by invoking it's name as it's executable.

```bash
./your_node.py
```
You can see the log message printed in the terminal, once. Let's modify our node to keep it running. We will add a loop to keep the node alive until we shut it down. After the log message, we will add a spin command to keep the node running.

```python
rclpy.spin(node)  # Keep the node running
```

Now we want to install the package so we can run it from anywhere. We need to modify the `setup.py` file in the package folder. Open the `setup.py` file and add an entry point for our node in the `entry_points` section. Like this:

```python
entry_points={
        'console_scripts': [
            # add this line which is <executable_name> = <package_name><file_name>:<function_name>
            "my_node = my_py_pkg.my_node:main" 
    },
```
save the file, go back to the terminal, navigate to the workspace root (*** YOU NEVER BUILD IN SRC YOU BUILD IN THE ROOT OF THE WORKSPACE ***) and build again with `colcon build`. 

We will need to source the workspace again to make the new package available:

```bash
source install/setup.bash
```
or add it to your `~/.bashrc` file to source it automatically every time you open a terminal:

```bash
source ~/workspace_name/install/setup.bash
```

Now we can run our node from anywhere using `ros2 run`:

```bash
ros2 run your_package_name your_node.py
```

With this you have created a simple ROS 2 node in Python, built it, and run it. Let's improve it my adding OOP concepts, and make it into a real template for future nodes.

### OOP Node Template

Instead of having everything in the main function, we will create a class that inherits from `Node`. This way we can encapsulate all the functionality of the node inside a class.

Let's start creating a class that inherits from `Node`:

```python 
class MyNode(Node):#We can name the class whatever we want, for example in a temperature sensor node we can name it TemperatureSensorNode
    def __init__(self):#We initialize the class, self refers to the instance of the class
        super().__init__("py_test") # Replaces the node creation in main
        self.get_logger().info("Node has been started, hello Node")
```

Now we modify the main function to create an instance of the class and spin it:

```python
def main(args=None):
    rclpy.init(args=args) # Initialize rclpy
    my_node = MyNode()  # Create an instance of the MyNode class
    rclpy.spin(my_node)  # Keep the node running
    rclpy.shutdown()      # Shutdown rclpy
```

Remember to save, build and source after every change.

### Timer Function

We will add a timer to our node that will print a message every second. First let's create a callback function that will be called by the timer inside the class:

```python
def timer_callback(self):
    self.get_logger().info("Timer callback called")
```

In our class, we will use the `create_timer` method to create a timer.

```python
class MyNode(Node):
    def __init__(self):
        super().__init__("py_test")
        self.get_logger().info("Node has been started, hello Node")
        self.create_timer(1.0, self.timer_callback)  # Create a timer that calls timer_callback every 1 second
```

Test it by saving, building, sourcing and running the node again. You should see the timer callback message every second.

Let's go a little further and add a counter that increments every time the timer callback is called.

in our initializer, we will add a counter variable:

```python
class MyNode(Node):
    def __init__(self):
        super().__init__("py_test") 
        self.get_logger().info("Node has been started, hello Node")
        self.counter=0 # Initialize counter
        self.create_timer(1.0, self.timer_callback)
``` 
and modify the timer callback to increment and print the counter:

```python
def timer_callback(self):
        self.get_logger().info("Timer callback called" + str(self.counter))
        self.counter += 1
```


## Create a Topic

We will use our template to create a publisher and subscriber. Let's duplicate our node file and name it `template.py`. Just so that we have a clean template to work with in the future. We will duplicate it again and name it `my_publisher.py` and `my_subscriber.py` for our publisher and subscriber nodes.

### Write a Publisher

Inside our main class during initialization we will create a publisher. A publisher needs a topic name, a message type and a queue size. Because of this let's check what message types are available in ROS 2. We can check the available message types with the following command:

```bash
ros2 interface show example_interfaces/msg/String
```

we can see that the String message type has a single field called `data` of type `string`. We will use this message type for our publisher. So we'll import it:

```python
from example_interfaces.msg import String
```

before going further, we added a new impor which means we need to add a new dependency to our package. Open the `package.xml` file and add the following line inside the `<depend>` tags:

```xml
<depend>example_interfaces</depend>
```
Now we can create the publisher in our class initializer:

```python
class myPublisher(Node):
    def __init__(self):
        super().__init__("my_publisher")
                                              #(type, topic name, queue size)
        self._publisher = self.create_publisher(String, "robot_talk", 10)
```

THis publisher wont do anything yet, so let's create a method that will publish a message every second using a timer. 

```python
def talk(self):
        msg = String()
        msg.data = "Hello"
        self.publisher_.publish(msg)
```
This method creates a String message, sets its data(remember it's data because it inherited from the interfaces.msg which had a `data` field) to "Hello" and publishes it. Now we will create a timer that calls this method every second and a log message that publisher has started.

```python
def __init__(self):
        super().__init__("my_publisher")
        self.publisher_ = self.create_publisher(String, "robot_talk", 10)
        self.create_timer(1.0, self.talk)
        self.get_logger().info("My robot is talking on a topic")
```
we can test it by saving, building, sourcing and running the publisher node. You should see the log message once, but nothing else will happen because we don't have any subscribers yet. we can verify that the topic is being published with:

```bash
 ros2 node info /my_publisher
```
which will show the topics being published by the node, or:
```bash
    ros2 topic list
```  
which will show all topics being published in the system, you should see `robot_talk` in the list, or finally you can use:
```bash
    ros2 topic echo /robot_talk
```
which will print the messages being published on the topic.

### Write a Subscriber

We have our publisher, now let's create a subscriber that listens to the `robot_talk` topic. We will create a new file called `my_subscriber.py` and implement the subscriber node there.

We will import the same message type as the publisher, and create a method for a callback that will be called when a message is received.

```python
def callback_receive_info(self, msg: String): #its receiving a msg of type String
        self.get_logger().info(msg.data) #print the data field
```

Now we create the subscriber in the class initializer:

```python
def __init__(self):
    super().__init__("Listener") 
    self.subscriber = self.create_subscription(
        String,"robot_talk", self.callback_receive_info,10)
       # type, topic name, callback function, queue size
``` 

Before building, remember to add the console script entry point in the `setup.py` file.
```python
 entry_points={
        'console_scripts': [
            "my_node = my_py_pkg.my_node:main",
            "my_talk = my_py_pkg.my_publisher:main",
            "my_listen = my_py_pkg.my_subscriber:main"
        ],
    },
```

Now we can save, build, source and run the subscriber node in a new terminal. If we have the publisher running, we should see the messages being printed in the subscriber terminal.

Now before finishing lets try running multiple publishers and one subscriber, by renaming from the terminal the publisher node to `my_talk_1`, `my_talk_2`, etc. and see how the subscriber receives messages from both publishers, in your terminal run:

```bash
ros2 run my_py_pkg my_talk --ros-args -r __node:=my_talk1
```
and in another terminal run:

```bash
ros2 run my_py_pkg my_talk --ros-args -r __node:=my_talk2
``` 
You should see messages from both publishers in the subscriber terminal, this is because we are forcing the node name to be different for each publisher using the `-r __node:=<new_name>` argument.

`r` mean remap, and `__node` is a special argument that allows us to change the node name at runtime. We can even remap topics this way if needed. For example:
```bash
ros2 run my_py_pkg my_talk --ros-args -r robot_talk:=robot_chatter
```
