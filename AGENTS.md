# Course documentation

- Write student-facing documentation in English for advanced university students.
- Use concise, objective, pragmatic language. Keep only facts, tasks, technical explanations, and assessment requirements students need.
- Use short, direct sentences. Avoid filler, repeated content, hand-holding, and motivational justifications.
- Do not include commentary about revisions, website completeness, implementation phases, or navigating the site in student-facing pages.
- Do not use emojis in documentation.
- Preserve approved assessment policies and existing technical material unless the current task authorizes changes.

# Review boundaries

- Work only within the segment explicitly authorized by the instructor.
- The current segment is site structure, the course landing page, and Course Overview.
- Address feedback within that segment. Do not begin another segment without explicit authorization after instructor review.
- Use small, logically grouped local commits. Do not push or publish without explicit authorization.
